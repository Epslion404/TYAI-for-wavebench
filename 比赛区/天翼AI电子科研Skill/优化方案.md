- 来源：`tianyi-electronics-skill-问题日志与优化建议-2026-09-29.md`（TeleAgent 工作空间，R&S RTM2032 两轮实机实测 + 全量源码走查）
- 日期：2026-09-29
- 适用范围：`比赛区/天翼AI电子科研Skill/`

## 一、硬约束（先定方向，再谈改法）

1. **轻量层自足**：`src/tianyi_electronics_skill/` 只用 Python 标准库。实机环境可能连 `numpy`／`RsInstrument`／`pyvisa` 都没有（评测环境即是如此），新的 fetch／plot／analyze 能力一律不引入第三方依赖。
2. **保留快照**：`wavebench/` 继续随包分发，作为高级用法（run plan、报告、插件）与语义参考；但文档必须写明它在缺少 `numpy` 时不可执行。
3. **抄语义不 import**：从 `wavebench/src/wavebench/transport/binary.py` 借分帧与字节记账语义，实现仍放在轻量层。
4. **失败必须可区分**：`unsupported`（命令被设备拒绝）、`parse_error`、`transport_error`、`timeout` 四类不得混为一谈，且所有输出带 `device_errors`。

## 三、实施计划

### P0（本轮实施）

- [x] **P0-A `fetch` 波形命令**
  - `core.py`：新增 `parse_block_header()`、`read_definite_block()`（跨 `recv` 分包、payload 含 `#`／`\n`、声明长度不足与超限均结构化失败）、`ScpiSession`（单连接复用、可配超时）、`read_waveform()`（`FORM REAL` + `FORM:BORD LSBF` + `<chan>:DATA:HEAD?` → 二进制块 → 时间轴与指标）。
  - `HEAD?` 的字段顺序在不同厂商／固件上不一致，因此实现取 `xstart,xstop,xinc` 解析并**做一致性校验**（`(xstop-xstart)/xinc` 与样本数比对）；不一致时输出 `header_consistent: false` 警告、`frequency_hz` 置空，并要求 `--sample-rate` 显式给出，绝不静默编造采样率。原始响应保留在 `header_raw`。
  - 支持 `--format real|ascii`、`--sample-rate` 覆盖、`--output *.csv|*.json` 落盘、`--include-samples` 内联到 stdout。
- [x] **P0-B 方言探测 + 诚实失败**
  - `detect_vendor()` 按 `*IDN?` 归类（r&s／rigol／keysight／tektronix／siglent／unknown），决定候选命令顺序。
  - 每个指标按候选风格逐个探测，**每条命令后用 `SYST:ERR?` 验证**，只接受"可解析且队列干净"的响应；输出记录 `commands`（实际生效命令）与 `unsupported`（含被拒命令与错误码）。
  - 候选表数据化（`DIALECT_STYLES`），实机确认一个型号后加一行即可；R&S 的正确语法仍待实机固化，不凭记忆硬编码。
- [x] **P0-C 错误队列上报**
  - `ScpiSession.drain_errors()` 循环读 `SYST:ERR?` 至 `0,"No error"` 或上限，统一输出 `device_errors`。
  - `inspect` 的空通道状态改为 `null` + `unsupported` 标记。
  - `measure` 全部指标不支持时，默认自动降级 `fetch → analyze_samples`（`--no-fetch-fallback` 可关）。
- [x] **P0-D 测试**
  - 新增 `tests/fake_scpi.py`（线程 + `socket` 的脚本化假服务器，支持文本与二进制块、分包发送）与对应用例：块解析边界、fetch 端到端、方言回放、空响应→`unsupported`、错误队列、inspect 空通道、fetch 降级。

## 五、实施细节与已知限制

- **空响应代价**：设备拒绝命令时通常不回包，客户端必须等满 `timeout` 才能判定为空响应。一台完全不支持远程测量命令的设备（如本次 R&S RTM2032 06.010）走完 6 指标 × 2 风格需要约 `12 × timeout`，实战建议 `--timeout 0.3`～`0.5`，或直接用 `fetch`。
- **性能**：探测命中同一风格后其余指标仍会重试该风格；这是为了逐指标给出可核对的原因，暂不做跨指标短路优化。
- **待实机固化**：`DATA:HEAD?` 字段顺序按 `xstart,xstop,xinc` 解析并做一致性校验；不一致时输出 `header_consistent: false` 与警告、`frequency_hz` 置空，需要 `--sample-rate` 显式给出。R&S 的测量命令语法与 HEAD 字段顺序仍待一次实机确认后写进 `dialects.py` 与本文档。
- **格式变更**：`inspect` 的通道状态由「空串」改为 `{"display": null, "unsupported": ...}`；`measure` 用 `unsupported` 取代旧的 `unsupported_or_errors`（按仓库规则不做兼容层）。

## 六、待确认

- R&S RTM2032 06.010 的测量与 `DATA:HEAD?` 语法需实机确认后固化候选表；当前策略是运行时探测 + 一致性校验，未确认前不会输出可疑频率。
- mDNS／VXI-11／HiSLIP 是否纳入（工作量大，收益取决于目标仪器；RTM2032 走 5025 足够）。
- analyze 的 FFT／THD 是否要做（受点数与标准库性能限制，建议单列一轮）。
