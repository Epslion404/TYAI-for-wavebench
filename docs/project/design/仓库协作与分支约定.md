# 仓库协作与分支约定

本页固定 2026-09～10 期间定下的仓库结构、服务范围与远端职责，供所有 contributor 与新会话遵循。细节与最新状态以两份 `AGENTS.md`（`competition` 与 `master` 各一份）为准。

## 服务范围（2026-10-02 起）

**本会话与两条分支只服务 `Epslion404/TYAI-for-wavebench`（`tyai`）。**

- 所有 issue、PR、Release、打包与评审都发生在 `tyai`。
- `origin`（公开 fork）与 `upstream`（`Scaxlibur/WaveBench`）**只作历史镜像保留**，不再作为工作目标：不为它们准备分支、不向上游提 PR、不做它们的评审跟进。
- 仍需联网时照旧：git 手动带 `-c http.proxy=http://127.0.0.1:7897`。

## 一句话结构

- `competition` = **比赛提交线**，也是**作品包（`比赛区/`）的唯一事实源**：提交、打包、发布都从它出。
- `master` = **Core 主线**：上游基座 + advisor 实施，**不含 `比赛区/`**。

## 平台使用约定（issue 与文件的分工）

**契约与验收留在文件，执行状态搬到 issue。**

- **文件（`docs/project/**`）**：RFC 合同、决策、验收门、边界、规范——稳定事实，跟代码一起评审与版本化。
- **平台（issue／milestone／label／Release）**：谁在做、做到哪、讨论、依赖、进度。
- **互链**：issue 里写「契约见 RFC §x」；文件里只写 issue 编号与状态摘要。**不要在文件里维护进度勾选**，否则两边必然漂移。

## 提交与验证

- 提交信息沿用上游约定：`feat|fix|docs|test|chore|refactor|perf(scope): 说明`，正文以英文为主。
- Core 改动合并前跑：`ruff check .`、`python -m pytest -q`、`python scripts/generate_docs.py --check`、`python .agents/skills/wavebench-docs/scripts/audit_docs.py --quiet-warnings`。
- 包内改动另跑：`cd 比赛区/天翼AI电子科研Skill && python -m pytest -q`（包内 `pyproject.toml` 已设 `testpaths = ["tests"]`，不会去收集内嵌快照的测试）。
- 本机网络：git 手动带 `-c http.proxy=http://127.0.0.1:7897`；`gh` 需要 `$env:HTTPS_PROXY`（直连会超时，偶发 `SSL_ERROR_SYSCALL`／HTTP 500，重试即可）。
