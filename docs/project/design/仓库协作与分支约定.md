# 仓库协作与分支约定

本页固定 2026-09～10 期间定下的仓库结构、远端职责与上游边界，供所有 contributor 与新会话遵循。细节与最新状态以两份 `AGENTS.md`（`competition` 与 `master` 各一份）为准。

## 一句话结构

- `competition` = **比赛提交线**，也是**作品包（`比赛区/`）的唯一事实源**：提交、打包、发布都从它出。
- `master` = **Core 主线**：上游基座 + advisor 实施，**不含 `比赛区/`**。
- 公开 fork = 上游镜像；上游仓库只接受**聚焦 PR**。

## 分支与远端职责

| 位置 | 用途 | 规则 |
| --- | --- | --- |
| `competition`（本地 + `tyai`） | 比赛提交线、作品包唯一事实源 | 改包只在这里；不要 merge/rebase 上游历史；不向上游提 PR |
| `master`（本地 + `tyai`） | Core 主线（上游 + advisor） | 不含 `比赛区/`；**不要推到 `origin`** |
| `origin` = `Epslion404/wavebench` | 公开 fork | 只作上游镜像与聚焦 PR 的来源；`master` 已回上游状态 `44506c4` |
| `tyai` = `Epslion404/TYAI-for-wavebench` | private 比赛仓库 | 默认分支 `master`；issue 与 PR 跟踪在这里；Actions 已关闭 |
| `upstream` = `Scaxlibur/WaveBench` | 上游（只读） | push URL 设为 `no_push`；面向上游的分支从 `upstream/master` 拉 |

## 作品包规则

- 只在 `competition` 上修改 `比赛区/天翼AI电子科研Skill/`；`master` 已移除该目录。
- 包内 `wavebench/` 是根项目的**独立快照**：改根目录不会影响它，反之亦然；要同步就整目录覆盖，并重跑包内测试。
- 包内代码只用标准库；`numpy`／`pyvisa`／`python-can` 一律作为可选 extras，默认安装不引入。
- **不提交 zip 归档**：打包产物走 GitHub Release（挂在 `tyai`）。

## 上游边界

- 比赛内容不面向上游：`#27`（比赛包）与 `#28`（advisor 聚焦实施草稿）都已关闭。
- 需要上游协作时：从 `upstream/master` 拉聚焦分支 → 推到 `origin`（fork）→ 开 PR；PR 里只出现与该主题相关的文件。
- 不要从 `master` 或 `competition` 直接向上游开 PR。

## 提交与验证

- 提交信息沿用上游约定：`feat|fix|docs|test|chore|refactor|perf(scope): 说明`，正文以英文为主。
- Core 改动合并前跑：`ruff check .`、`python -m pytest -q`、`python scripts/generate_docs.py --check`、`python .agents/skills/wavebench-docs/scripts/audit_docs.py --quiet-warnings`。
- 包内改动另跑：`cd 比赛区/天翼AI电子科研Skill && python -m pytest -q`（包内 `pyproject.toml` 已设 `testpaths = ["tests"]`，不会去收集内嵌快照的测试）。
- 本机网络：git 手动带 `-c http.proxy=http://127.0.0.1:7897`；`gh` 需要 `$env:HTTPS_PROXY`（直连会超时，偶发 `SSL_ERROR_SYSCALL`／HTTP 500，重试即可）。

## 已知坑（详细版见 `AGENTS.md`）

- 本机有两个**基线失败**，与改动无关：`test_windows_job_rejects_allocation`（OpenBLAS 内存耗尽形态不符）与 `test_tui_power.py` 的 busy 时序用例（flaky，单独跑 3 次约错 2 次）。判断回归前先用 `git diff upstream/master -- <path>` 确认代码未改。
- `docs/development/documentation.md` 要求给审计器传 `--term-allowlist`，但脚本已无该参数。
- 历史提交（`68148a0`／`a9e49e3` 等）里仍可按 SHA 取到比赛包内容——分支树已清理，但对象未被 GC。
